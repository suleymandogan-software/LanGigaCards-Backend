# Architecture

## Repository layout

```
LanGigaCards.slnx            Solution — open this, not a project file
Directory.Build.props        Settings shared by every project (framework, nullability)
.editorconfig                Style rules, enforced at build time
docs/                        This documentation
.github/workflows/ci.yml     Build + test on every push and pull request
src/
  LanGigaCards.Api/
    Controllers/             HTTP surface — one controller per resource
    DTOs/                    Request and response shapes; validation attributes live here
    Entities/                EF Core model — the shape of the tables
    Data/                    DbContext, schema configuration, seed data
    Migrations/              Generated by dotnet-ef; never hand-edit
    Interfaces/              IUnitOfWork, IGenericRepository, IEmailService
    Repositories/            Their EF Core implementations
    Services/                Logic with no HTTP in it: scheduling, XP, summaries, mail
    Program.cs               Composition root: DI, auth, rate limits, pipeline
tests/
  LanGigaCards.Api.Tests/    xUnit — integration tests plus StudyEngine unit tests
```

The `src/` + `tests/` split is the .NET convention, and it earns its keep here: the
solution at the root means an IDE opening the repository finds everything, and
`Directory.Build.props` means the tests cannot silently target a different framework than
the code they test.

## Layering

Requests flow **Controller → IUnitOfWork → Repository → DbContext**. Controllers own HTTP
concerns (status codes, model validation, reading the caller's id from the JWT) and
nothing else; anything worth testing without a request lives in `Services/`.

`Services/StudyEngine` is deliberately static and dependency-free — the spaced-repetition
schedule, the XP curve and the streak calculation are pure functions of their inputs.
That is what makes them cheap to pin down in tests, and it is where a scheduling bug
would do the most damage if it went unnoticed.

## Data integrity

The schema is not just what EF needs to save an object. `Data/SchemaConfiguration.cs`
bounds every text column and adds 23 CHECK constraints that restate the DTO validation
rules at the table level, so invalid data cannot reach the database through any path — not
through a controller with a missing attribute, not through a migration, not through a
hand-written `UPDATE`.

This costs something in testing: an in-memory provider ignores constraints entirely, so
the tests use SQLite instead (see below).

## Testing

`tests/LanGigaCards.Api.Tests` uses `WebApplicationFactory<Program>`, which boots the
pipeline Program.cs actually builds — the same routing, JWT validation, rate limiting and
model binding. Tests therefore exercise auth the way a client does, rather than calling
controller methods directly with a hand-made `ClaimsPrincipal`.

Two decisions are worth knowing before you add tests:

**SQLite, not the in-memory provider.** The in-memory provider is not a database: it has
no constraints, no foreign keys, and no CHECK enforcement. Given how much of this
schema's correctness lives in constraints, testing against it would prove very little.
The price is one shim — `LEN()` is T-SQL, SQLite spells it `LENGTH`, and SQLite rejects
`CREATE TABLE` outright when a CHECK names a function it does not know — so
`LanGigaCardsApiFactory` registers a `LEN` function on the connection before
`EnsureCreated` runs.

**The test project pins `RollForward` to `LatestPatch`.** The API rolls forward to the
latest major so contributors do not all have to install the same runtime. The test host
must not: on .NET 10 that runtime's `System.Text.Json` calls `PipeWriter.UnflushedBytes`,
which the 8.0 TestHost response writer does not implement, and every request through the
test server fails while serialising its response.

**Rate limits apply in tests too.** Login allows 5 attempts per 5 minutes and register 10
per 15, partitioned by client IP — which is a single partition under the test server. A
test class that registers a dozen users will start getting 429s. Give a heavy class its
own factory rather than sharing one.
